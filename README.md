## 核心区别：主备复制和存算分离是两套思路

两者的根本差别在架构上。RDS MySQL 高可用系列是一对主备节点部署在同一地域：主库承担全部读写，备库通过半同步复制接收数据变更；主库出问题时自动提主，切换通常 30 秒内完成，连接地址保持不变，应用端感受到的只是一次短暂断连和重连。这套架构里有个容易被忽略的细节——备库不可读，它唯一的职责就是等着接替主库，想给读加能力得另买只读实例。

PolarDB 把计算和存储拆开了。底层存储用 Optane 持久内存（3D XPoint）、NVMe SSD 和 RDMA 网络，I/O 与网络协议栈整体放进用户态来压低延迟；写入走 Quorum 机制，数据至少写到 3 个副本中的 2 个才确认成功，存储层因此同时拿到数据冗余和强一致。内核层面还针对锁、I/O 路径和大表的高并发处理做了专门优化。

一句话收拢：RDS 用主备复制做冗余，PolarDB 靠多数派写入加分层的存储体系做冗余；前者的扩展单位是实例，后者的扩展单位是节点。

## 读扩展的差别：备库不能读，只读节点才是干活的

RDS 的读扩展靠只读实例。备库只管容灾，读请求的分担要由另购的只读实例承接；PolarDB 的集群由主节点和只读节点组成，加节点就能扩读能力。

这里要纠正一个常见误会：有人以为 RDS 主备架构天然就是读写分离，实际上高可用系列里的备库不对外提供读服务，它存在的前提只有一个——主库挂了它顶上。要读扩展，请走只读实例，和备库是两种资源。

## 单条 SQL 谁更快？这个问题本身就问偏了

直接拿一条 SELECT 对比两个产品的延迟，结果很可能误导你。官方基准文档专门说明了原因：PolarDB 采用存算分离，单条查询的网络延迟可能比 RDS 更高，但生产环境里缓存命中率通常超过 99%，只有第一次读会真正碰到磁盘 I/O，后续读全部命中缓冲池，实际表现和 RDS 相当。

想测出有参考价值的数字，注意三点：对比读性能别用单条 SQL，要用模拟生产负载或 Sysbench；对比写性能要用压测；对标方式要公平——PolarDB 集群（主节点 + 只读节点）对应 RDS（主库 + 半同步只读），因为 PolarDB 的 Quorum 写入和半同步复制才处于同一一致性档位，拿异步复制来比没有意义。官方 OLTP 基准覆盖了 PolarDB MySQL 8.0.1 对 RDS MySQL 8.0、5.7 对 5.7、5.6 对 5.6 的多组版本。

## 引擎支持范围：SQL Server 和 MariaDB 只有 RDS 有

引擎清单直接决定可选范围。RDS 支持四种引擎：MySQL、PostgreSQL、SQL Server、MariaDB；PolarDB 目前提供 MySQL 兼容和 PostgreSQL 兼容两类内核，MySQL 侧覆盖 8.0.1、5.7、5.6 三个版本线。结论很简单：业务跑在 SQL Server 或 MariaDB 上，PolarDB 没有对应内核，只能留在 RDS；用 MySQL 或 PostgreSQL 的，两边都能选。

## PolarDB 和 PolarDB-X 别弄混，后者是另一个产品

搜这个关键词的读者里，相当一部分会把 PolarDB 和 PolarDB-X 混在一起讲。它们是两个产品：PolarDB 是云原生数据库，可以加只读节点；PolarDB-X 前身是 DRDS，定位是分布式数据库，解决的是单库写瓶颈和跨库事务。

PolarDB-X 1.0 的架构偏“拼装”：它自己不带存储资源，要单独购买 RDS MySQL 实例做存储层，再到控制台挂载整合；扩容也偏手工，需要自己评估每台 RDS 的剩余容量，再把数据库分片迁到新实例。挂载的私有定制 RDS 可以选高可用或三节点企业版系列，存储层 MySQL 版本必须与计算层一致。另外，官方文档里有一条明确的警告：删除数据库分片之后，PolarDB-X 1.0 将无法访问这份数据。

PolarDB-X 2.0 把这些收拢成一体化服务：创建一个实例即可启用；存储层用三节点模式，基于 Paxos 协议做到零 RPO，存储层故障切换 SLA 不超过 30 秒，计算层切换以秒计；事务引擎为自研，支持全局 MVCC、两阶段提交（2PC）以及快照时间戳与提交时间戳；对外提供统一的二进制日志服务，用 DTS 订阅的方式和订阅一台单机 RDS 完全一样。计算节点基于 MySQL 5.7，存储节点对用户完全抽象，负载均衡、逻辑 binlog 和 HTAP 混合负载都由系统自动处理，扩容时加节点即可，数据自动均匀分布。

## 常见问题

### PolarDB 兼容 MySQL 吗？

兼容。PolarDB 提供 MySQL 兼容内核，覆盖 8.0.1、5.7、5.6 三个版本线，官方基准也是拿它和同版本线的 RDS MySQL 直接对测的。

### RDS 的备库能拿来跑报表吗？

不能。高可用系列的备库不对外提供读服务，职责只有容灾切换。报表这类读负载请用只读实例承接。

### 已经在用 RDS，值得迁到 PolarDB 吗？

看两个信号：只读实例是不是越加越多还没扛住读并发，以及数据增长是否已经让你频繁做容量规划。两条都中，迁移才有明确收益；只是跑个常规应用，留在 RDS 更省心，也省下迁移成本。

### PolarDB-X 1.0 删掉分片，数据还能找回来吗？

官方文档的警告写得很直白：删除数据库分片后，PolarDB-X 1.0 将无法访问该数据。动手清理前务必确认分片里没有还在使用的数据。
